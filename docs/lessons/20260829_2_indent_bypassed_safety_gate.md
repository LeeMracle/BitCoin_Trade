# 교훈 #49 — 들여쓰기 한 칸이 안전장치를 우회시켰다: 배치는 AST로만 검증된다

- **일자**: 2026-08-29 (기록 2026-08-31)
- **사고 유형**: 자작 회귀 (수정 작업이 만든 결함)
- **관련**: [ADR 20260829-1](../decisions/20260829_1_consec_cooldown_release.md),
  lessons #45(종료 코드가 TP 루프 안에 있어 도달 불가 — 같은 계열)

## 무슨 일이 있었나

5연패 쿨다운 데드락을 고치면서 **해제 분기를 `else:` 밖에 넣었다.**

```python
if consec >= CONSEC_LOSS_LIMIT:
    if alerted_until > now_ts or cd_until > now_ts:
        print("cooldown 활성 ... 알람 skip")      # 만료 전
    else:
        win_rate = ...
    # ↓ 12칸 — else 를 빠져나왔다. **무조건 실행된다.**
    _served = (지문 일치 여부)
    if _served:
        해제()                                    # 만료 여부와 무관하게 실행
```

의도는 `else:`(만료됨) **안**에서만 해제하는 것이었는데, 4칸을 덜 들여써서
`if alerted_until...` 과 형제가 됐다. 결과는 로그가 그대로 증언한다:

```
01:51:12  [5연패] cooldown 활성 (62.4h 남음) — 알람 skip
01:51:12  [5연패] 쿨다운 복역 완료 — floor=... 로 해제 (1회째)
```

**두 줄이 같이 나올 수 없는 구조인데 나왔다.** 쿨다운이 62.4시간 남았는데 해제됐고,
하락장에서 매수가 다시 열렸다 — 바로 그것을 막으려고 만든 장치였다.

## 왜 검증을 전부 통과했나

| 검증 | 결과 | 왜 놓쳤나 |
| --- | --- | --- |
| `ast.parse` 구문 검사 | 통과 | 문법은 완벽하다. 잘못된 위치도 유효한 파이썬이다 |
| 시나리오 시뮬레이션 4/4 | 통과 | **로직을 복제해서** 테스트했다 — 실제 파일의 들여쓰기와 무관 |
| 정규식 역방향 테스트 10/10 | 통과 | 텍스트에 무엇이 **있는지**만 봤다. 어디에 있는지는 안 봤다 |

> **"코드에 무엇이 있는가"와 "코드가 어디에 놓였는가"는 다른 질문이고,
> 후자는 AST 로만 물을 수 있다.**

시뮬레이션이 특히 위험했다. 로직을 별도로 옮겨 적어 검증하면 **옮겨 적는 순간
원본과의 연결이 끊긴다.** 4/4 통과가 주는 확신은 로직에 대한 것이지 배치에 대한
것이 아니었는데, 나는 그 구분 없이 "검증됐다"고 판단했다.

lessons #45 가 정확히 같은 계열이다 — 포지션 종료 코드가 TP 루프 **안에** 있어
구조적으로 도달 불가였고, 문자열 검사가 세 번 속은 뒤 AST 룰로 잡았다.

## 2차 피해 — 봇을 멈추고 재기동하지 않았다

사고를 인지하고 매수를 막으려 `systemctl stop` 했는데, 수정에 몰두하다가
**재기동을 잊었다.** 이틀 뒤 사용자 질문으로 발견됐다.

- 다행히 systemd 가 11분 뒤(02:03) 자체 기동했다 — 그러나 그때 서버 코드는
  **여전히 버그판**이었고, 내가 복구한 상태를 다시 즉시 해제해버렸다.
- 즉 "상태 복구"는 **코드를 먼저 고치지 않으면 무의미하다.** 나는 순서를 틀렸다.

## 수정

- 해제 분기를 `else:` 안(16칸)으로 재배치
- `pre_deploy_check.check_consec_cooldown_releases()` 에 **AST 배치 검증** 추가:
  - `if consec >= LIMIT` 노드를 찾고
  - 그 직속 `if` 가 정확히 1개인지 (2개면 해제가 밖으로 나온 것)
  - `_served` 가 활성판정의 **else 안에만** 있는지
  - 역방향 테스트: **실제 사고를 코드로 재현**(들여쓰기 -4)해서 적발 2/2

## 교훈

1. **배치 검증은 AST로.** 정규식·문자열·개수는 위치를 볼 수 없다.
2. **로직 복제 시뮬레이션은 배치를 검증하지 않는다.** 통과 범위를 명시할 것 —
   "로직 4/4"이지 "구현 4/4"가 아니다.
3. **상태 복구는 코드 수정 이후에.** 순서가 바뀌면 복구가 즉시 덮어써진다.
4. **봇을 멈췄으면 재기동까지가 한 작업이다.** 정지-수정-기동을 하나의 체크리스트로.
5. 안전장치를 고치는 작업은 **그 장치를 무력화할 위험**을 동반한다.
   이번엔 "해제를 실제로 되게" 하려다 "항상 해제"를 만들었다.

## 결과

사고 구간(08-29 02:03 ~ 08-31)에 매수가 재개되어 5건이 청산됐다:
ZKP +7.48% / ZKC +7.66% / SKR -10.49% / EGLD +7.10% / ERA -10.13% (3승 2패).

것은 명백한 결함이었다.
