# 교훈 #48 — 연결은 죽기 전에 먼저 썩는다: liveness 감시로 freshness를 지킬 수 없다

- **발단**: [research/20260827_1](../../workspace/research/20260827_1_slippage_filter.md)

- **계열**: #1(틱 vs 봉), #40(진행 중 봉을 읽은 필터), #47(정상 끊김을 오류로 집계)

## 무슨 일이 있었나

2026-08-27 09:55 UTC, KERNEL/KRW 를 **09:50 의 가격(57원)** 으로 판단해 매수했고
체결가는 67.8 이었다(+18.9%). 부풀려진 체결가 기준 하드손절(-10% = 61.0)이 실제
시세(58) 위에 깔려 **진입과 동시에 손절 영역**이 됐다.

처음엔 "호가창 슬리피지"로 진단했으나 측정이 그걸 반증했다:

| 측정 | 결과 |
| --- | --- |
| 분봉 재구성 600건 | 돌파 분 즉시 체결 시 슬리피지 **평균 -0.11%** — 호가창은 문제 아님 |
| 08-27 매수 6건 | **체결가는 6/6 모두 당시 분봉 안**. 어긋난 건 신호가뿐 |
| KERNEL 분봉 | 09:50 밴드 돌파(57.8) → 09:53 정점(69.8) → 09:55 매수(67.8) |

즉 집행이 아니라 **입력이 낡았다.**

## 진짜 원인

계측을 붙여 17시간 관측한 결과:

| 계열 | 평상시 | 열화 시 (68창 중 3창) |
| --- | --- | --- |
| 전송지연 (`now - timestamp`) | p50 **38ms** / p99 60~150ms | p50 **164초 / 347초 / 732초** |
| handler 소요 | p50 0.1ms / p99 0.2ms | — (변화 없음) |

그리고 열화 창의 시각을 웹소켓 이벤트와 대조하니:

```
07:18:54  전송지연 p50 164초   ← 이미 밀리는 중
07:33:54  전송지연 p50 732초   ← 더 밀림
07:37:40  웹소켓 연결 종료 → 5초 후 재연결
```

**연결은 죽기 전에 먼저 썩는다.** 메시지는 계속 오는데 몇 분씩 늦고, 그러다 끊긴다.
그 구간의 매수 판단은 전부 낡은 가격으로 내려진다.

## 왜 기존 방어가 통과시켰나

```python
msg = await asyncio.wait_for(ws.receive(), timeout=300)   # 5분간 "무소식"이면 재연결
```

이 장치는 **침묵(liveness)** 만 잡는다. `receive()` 가 반환되기만 하면 타이머가
리셋되므로, **12분 늦은 메시지가 계속 도착하는 상태는 영원히 통과**한다.

> **살아있음(liveness)과 신선함(freshness)은 독립적인 속성이다.**
> 하나를 재는 장치로 다른 하나를 지킬 수 없고, 감시도 따로 있어야 한다.

교훈 #47 에서 "정상 끊김을 오류로 세지 말라"고 고쳤는데, 이번에 보니
**끊기기 직전 구간이 진짜 위험**했다. 끊김 자체는 무해하고, 그 앞의 열화가 사고다.

## 수정

- `TickLagTracker.is_degraded()` — 최근 200틱 **중앙값**이 임계(10초) 초과 시 판정
  - 중앙값인 이유: 단발 지각 1건에 재연결하면 안 되고, 평균은 outlier 하나에 끌려간다.
    실측 열화는 **p50 자체가** 164~732초였으므로 중앙값에 정확히 잡힌다.
  - 임계 10초: 평상시 p99(0.15초)의 60배, 관측 최소 열화(164초)의 1/16 — 양쪽에서 멀다
- `note_reconnect()` — 재연결 시 창을 비우고 120초 쿨다운.
  **없으면 낡은 표본이 중앙값을 지배해 즉시 재판정 → 재연결 루프.**
- 강제 재연결은 `consecutive_errors` 를 올리지 않는다 (교훈 #47)
- 알림은 1시간 1회 디바운스 (교훈 #30) — 조치는 자동이므로 사람이 알아야 할 건
  "지금 열화 중" 한 번뿐이다
- 상수 4개는 `config.py` 단일 정의 (교훈 #19)

## 부수 교훈 — 룰이 이름을 묻는 순간 속는다 (7회째)

이번 룰의 초안이 역방향 테스트에서 2건 실패했다:

| 초안 | 왜 통과했나 |
| --- | --- |
| `"def is_degraded" not in tsrc` | `def is_degradedXX` 가 **부분문자열로 포함** |
| `re.search(r"_notify_ws_stale\(", src)` | **정의부 자신**(`async def _notify_ws_stale(`)에 매칭 |

같은 유형이 lessons #44(주석에 속음), #46(dict 키를 사유로 오인),
틱지연 룰(`tick_lag_msXX` 통과)에 이어 **7회째**다. 패턴이 분명하다:

> **룰이 "이름이 존재하는가"를 물으면 정의부·주석·유사이름이 전부 답이 된다.**
> 물어야 할 것은 "**호출부가 존재하는가**"이고, 그건 정의부와 문법적으로 구별되는
> 형태(`self.foo(`, `.foo(`)로만 잡힌다. 검사 대상이 아니라 **검사 형태**가 문제다.
