그런데 08-25 이후에도 실행 결함 수정이 이어졌다.

따라서 "표본이 몇 건인가"에 **41건(08-25 기준)과 11건(09-02 기준)** 두 답이 존재했고,
[ROADMAP](../ROADMAP.md) §3 에 열린 결정으로 올려두었다.

## 결정

**`strategy_start` 를 `2026-09-02` 로 이동한다.** `closed_trades` 70건은 **보존**하고
창만 옮긴다(삭제 아님 — ADR 20260823-1 과 동일 방식).

### 근거

1. **판정 기준 문서와의 일관성** — *"결함이 섞인 표본은 전략 성적이 아니다"* 를
   문서가 이미 못 박고 있다. 41건을 쓰면 그 규칙을 이번만 예외로 두는 것이 된다.
2. **혼입 결함이 매매 방향을 직접 바꿨다** — 교훈 #48은 진입 가격을, #49는 **하락장에서
   매수를 열었다**. 손익 부호에 직접 작용하므로 "약간의 노이즈"로 볼 수 없다.
3. **이 프로젝트가 반복한 실수의 정반대 방향** — 지금까지 14회의 파라미터 변경은
   전부 "빨리 답을 보려고" 기준선을 흔든 것이었다. 3주를 더 기다리는 선택은
   그 패턴을 처음으로 거스른다.

### 대가 (명시)

- **판정이 약 1주 → 약 3주로 늦어진다** (표본 41 → 11, n=50 까지 39건 남음)
- 08-25 ~ 09-01 의 **30건이 판정에서 빠진다** — 데이터는 보존되나 창 밖

이 대가는 사용자가 인지하고 수용했다.

### 🔴 승률 90.9% 를 성과로 읽지 말 것

n=11 은 판정 불가 구간이다([판정 기준](../strategy_improvement_criteria.md) §3-3:
n=30 에서도 CI 상한 57.7% 로 판정 불가). 이 프로젝트는 같은 표본을 반복해서 보다
한 세션에서 승률이 **50% → 33% → 40%** 로 흔들린 이력이 있다(다중검정).

**판정 시점은 n=50 으로 사전 고정되어 있고, 그때까지 승률을 근거로 어떤 결정도 하지 않는다.**

## 실행

봇이 `self.state` 를 메모리에 들고 `save_state()` 로 dict 전체를 저장하므로,
가동 중 파일 편집은 다음 저장에 덮어써진다 → **정지 상태에서만 편집 가능**.

```
13:18:29 UTC  systemctl stop
              strategy_start 편집 + 무결성 assert
13:21:47 UTC  systemctl start → active 확인
```

**정지 구간 약 3분 18초** — 계획서의 성공기준(60초 이내)을 **초과했다**(§ 회고 참조).
