# 슬롯 확대 x 비중 상한 결합 측정 (15 / 20)

- **일자**: 2026-08-25
- **발단**: 사용자 지시 "슬롯 늘려줘" → **15슬롯** 채택(20도 같이 측정). 그런데 `pre_deploy_check` 는
  `MAX_POSITION_WEIGHT <= 1.5 / MAX_POSITIONS` 를 강제한다(ADR 20260823-2).
  **08-24 슬롯 축 측정은 상한을 20%로 고정한 채 돌린 것**이라, 룰을 지킨 조합
  (15슬롯 → 상한 10%, 20슬롯 → 7.5%)이 같은 결과를 내는지는 측정된 적이 없었다.
- **방법**: `backtest_param_sweep.py --axis slot20 --runs 20`
  (45종목 / 700일 / 거래가능 366일, IS·OOS 분리, 무작위 선택 20회 평균)
- **주의**: 절대 수익률은 생존편향(상장폐지 코인 누락)으로 낙관 쪽. **상대 비교용.**

## 2. 읽는 법

### (a) 룰 준수 상한(7.5%)은 원래 측정과 구분되지 않는다

20% ↔ 7.5% 사이에서 **거래 수(148)·승률(65.2%)·건당 평균(1.92%)·MDD(-9.5%)가 동일**하고
IS/OOS만 ±0.7%p 흔들린다. 이유는 단순하다 — 20슬롯의 목표 비중은 5%라
상한 7.5%에 **닿는 일이 거의 없다**. 상한은 "빈 슬롯이 1~2개만 남았을 때"만 구속력을 갖는다.

→ **ADR 20260823-2의 룰을 지키면서 08-24 슬롯 측정 결과를 그대로 가져올 수 있다.**

### (b) 그런데 5%(균등비중)까지 조이면 나빠진다

OOS +15.7% → +13.2%. 상한이 목표 비중과 같아지면 현금이 남는 구간이 생긴다
(`available x 0.95 / 빈 슬롯` 이 목표보다 클 때 잘라내므로).
**상한은 목표 비중보다 여유가 있어야 한다** — 1.5배(7.5%)가 그 여유다.

### (c) 기준선 값이 08-24와 다르다 (측정 노이즈의 크기)

| | 08-24 측정 | 08-25 측정(오늘) |
|---|---:|---:|
| 종목 수 | 44 | 45 |
| 슬롯5 IS | -12.5% | -10.0% |
| 슬롯5 OOS | +2.4% | +7.0% |
| 슬롯20 IS / OOS | +7.4% / +16.1% | +6.6% / +15.9% |

종목군이 하루 사이 1개 늘고 IS/OOS 경계일이 이틀 밀린 것만으로 **슬롯5 OOS가 4.6%p 움직였다.**
슬롯20은 0.2%p만 움직였다 — 이것 자체가 §1의 핵심 주장(슬롯이 적으면 결과가 운에 좌우된다)의
독립적인 증거다. **슬롯5의 숫자는 소수점을 믿을 게 못 되고, 슬롯20은 상대적으로 안정적이다.**

## 3. 결론

`MAX_POSITIONS = 15` / `MAX_POSITION_WEIGHT = 0.10` 를 채택한다
(측정상 최고는 20이지만 생존편향 노출과 최소주문 마진을 이유로 15 선택) → [ADR 20260825-1](../../docs/decisions/20260825_1_slot_expansion.md)

측정이 답하지 **못한** 것(ADR §4에 위험으로 기록):
1. 생존편향 — 슬롯이 많을수록 한계 알트를 더 담아 편향에 더 노출된다
2. 시뮬레이터는 **부분 익절의 최소주문 격하**를 모델링하지 않는다
   (실코드는 매도금 < 5,000원이면 전량 매도로 바꾼다). 자산이 157,895원(슬롯15 기준) 밑이면 실제와 갈린다
3. 전환기 — 기존 5종목이 자본을 붙들고 있는 동안은 슬롯당 금액이 최소주문 미달이라
   신규 매수가 멈춘다. 자기해소되지만 며칠 걸린다

## 4. 재현

```bash
PYTHONUTF8=1 python scripts/backtest_param_sweep.py --axis slot20 --runs 20
```

> (결과표 직전에 죽어 30분 날림)를 `sys.stdout.reconfigure`로 차단했다.
