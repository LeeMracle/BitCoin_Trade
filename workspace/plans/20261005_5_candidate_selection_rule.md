## 1. 목표

신호가 한 시간 안에 여러 개 몰릴 때 **무엇을 먼저 살지**를 정하는 규칙이 수익·낙폭을 개선하는지 판정한다.
현재는 틱 도착순(= 사실상 무작위). 기존 연구가 "선택 순서가 결과를 14%p 좌우"라고 기록했다.

### 사전 진단 (이미 실행, 규칙 평가 아님)

| 진단 | 값 |
| --- | --- |
| 후보 중 슬롯·안전장치로 탈락 | IS 21~23% / OOS 32~33% (안전장치 탈락 포함 → 선택 가능 폭의 **상한**) |
| 같은 hour 에 2개 이상 겹친 신호 | 507개 중 320개 (63%), 최대 동시 27개 |
| `simulate` 회귀 | 훅 추가 후 기존 키 7개 × 20건 **불일치 0** |

### 실거래 구현 제약 (연구 설계에 반영)

실거래는 신호가 틱에 도착하는 **즉시** 매수한다. 백테스트처럼 같은 시간 후보를 모아 순위를 매기는 것은 **비인과적(oracle)** 이다.
따라서 2단계로 간다: A) oracle 순위로 **상한**을 잰다(무의미하면 즉시 종료) → B) 인과적 규칙(도착 시점에 알 수 있는 값의 고정 임계 필터)으로 환산해 재검증.

## 2. 가설 (사전 고정) — 특성은 전부 **전일(d-1) 이하 데이터만** 사용 (look-ahead 금지)

| ID | 규칙 (먼저 살 후보) | 특성 정의 | 근거 가설 |
| --- | --- | --- | --- |
| R1 | 거래량 급증이 큰 것 | `volume[d-1] / mean5(volume)[d-1]` 큰 순 | 돌파에 참여자가 몰린 것이 지속된다 |
| R2 | 변동성 낮은 것 | `atr[d-1] / close[d-1]` 작은 순 | 같은 -6% 손절에서 노이즈 손절이 적다 |
| R3 | 30일 상대강도 높은 것 | `close[d-1] / close[d-31] - 1` 큰 순 | 모멘텀 지속 |
| R4 | 유동성 큰 것 | `mean5(volume*close)[d-1]` 큰 순 | 슬리피지·체결 신뢰 |

- 동률은 무작위(`rng`)로 깬다. 파라미터 자유도 0 (창 길이 5/14/30 은 위에서 고정).
- **대조군**: C0 무작위(seed 0~9, 기존 방식) · C1 무작위 재추출(seed 100~109, **잡음 바닥 측정**) · 각 규칙의 **역순**(방향 점검).
- 시도 수 공개: 후보 4 + 역순 4 + 대조 2 = 10 변형.

## 3. 채택 기준 (사전 고정)

단계 A (oracle 상한) — 규칙 R 이 **모두** 만족해야 통과:

1. IS·OOS **각각**에서 평균 수익이 C0 대비 `+max(2.0%p, 2·√2·SE_C0)` 이상. (`SE_C0 = std(C0 10회)/√10`, 구간별)
2. IS·OOS **각각**에서 MDD 가 C0 보다 1.0%p 넘게 나빠지지 않는다.
3. 역순이 IS·OOS **둘 다** C0 보다 나쁘다 (방향이 의미 있는지; 역순도 좋아지면 잡음으로 판정).
4. 통과가 둘 이상이면 `min(IS 개선, OOS 개선)` 이 큰 것 하나만 단계 B 로.

단계 A 에서 **0개 통과 → 결론 "선택 규칙은 개선 레버가 아니다"로 종료**(음성 결과도 기록).

단계 B (인과 환산) — 단계 A 승자만:

- 규칙을 "특성 ≥ 임계" 필터로 환산. 임계 = **IS 신호 분포의 중앙값**(하나로 고정, 튜닝 금지), OOS 에서만 평가.
- 통과: OOS 수익이 C0 보다 `+max(2.0%p, 2·√2·SE_C0)` 이상이고 MDD 악화 ≤ 1.0%p, 그리고 단계 A 개선의 50% 이상 보존.
- 통과 시에도 **실거래 반영은 사용자 결정** (`strategy_start` 리셋 비용: 표본 0 부터 재누적).
