## 3. 오늘 처리분

### (a) 슬롯 5 → 15 (ADR 20260825-1)

포트폴리오 무수익(ADR 20260823-2)의 원인은 전략이 아니라 **용량**이었다.
5슬롯은 신호의 27%만 취해 *선택 운*이 결과를 지배한다.

| 슬롯 | IS | OOS | MDD | 승률 | 필요표본 |
|---|---:|---:|---:|---:|---:|
| 5 (이전) | -10.0% | +7.0% | -20.3% | 59.9% | 493 |
| **15 (현행)** | **+3.4%** | **+14.2%** | **-12.9%** | **62.6%** | **109** |
| 20 | +7.3% | +15.7% | -9.5% | 65.2% | 64 |

개선의 실제 메커니즘은 **OOS 편차 4.2% → 2.7%**(선택 운의 소멸)다.
20이 측정상 더 좋지만 생존편향 노출과 최소주문 마진 때문에 15를 택했다.
동반: 비중 상한 0.20 → 0.10(검증룰 `상한 ≤ 1.5/슬롯`). 측정상 룰 준수 상한은
원래 조건과 구분되지 않으나, **균등비중까지 조이면 나빠진다**(현금이 논다).

부수 적발: 슬롯 수 리터럴 3곳(`보유 N/5`)이 알림·보고 경로에 박혀 있었다 — 교훈 #19의 표시 버전.

### (b) 수동 개입과 전략 성적의 분리 — lessons #46

`closed_trades`는 **검증표본 · 5연패 브레이커 · 일일보고 승률의 공통 입력**이다.
사람이 개입한 청산이 섞이면 셋 다 오염된다. 실측으로 두 가지가 재현됐다:

- "전략 1건인데 2건 승률 100%"
- 수동 손실 3건 + 전략 손실 2건 = **연패 5 → 72h 매수 중단**(전략은 멀쩡한데 멈춘다)

→ `services/execution/trade_class.py`(strategy/manual/repair/unknown, **allowlist**) 신설,
통계 2곳·연패 2곳에 동일 적용. `scripts/manual_close_position.py`로 매도와 회계를
한 트랜잭션으로 묶음(봇 정지 강제 + 확정 체결가 + `daily_pl` 기록).

⚠ **unknown은 통계에서 제외, 연패에는 포함** — 각 경로가 안전한 쪽으로 틀리게 한 의도적 비대칭.

### (c) 웹소켓 정상 끊김이 봇 자동중지로 번지던 문제 — lessons #47

`Cannot write to closing transport`는 업비트가 연결을 정리할 때 나는 **정상** 사건인데
`consecutive_errors`로 집계됐다. 게다가 `_reset_errors()`가 **매수/매도 성공 두 곳에만**
있어 거래가 드문 이 봇에선 카운터가 내려갈 방법이 없다 → 5회 누적 시 봇 자동중지.

→ `is_benign_ws_error()` 신설(시간당 10회 이상일 때만 알림) + **틱 수신 시 reset**.

## 4. ⚠ ML 게이트는 3개월 넘게 꺼져 있었다

CLAUDE.md에는 "ML 게이트(threshold 0.45)"가 메인 전략 구성요소로 적혀 있었으나,
서버 `systemd drop-in`이 `ML_FILTER_ENABLED=0`을 강제하고 있었다(2026-05-16, ADR 20260515-1).
최근 shadow 로그의 `score: 1.0`은 모델 출력이 아니라 **비활성 자리표시자**다.

세 가지가 더 나왔다:

1. **"차단 없이 점수만 기록"이 코드상 불가능** — `is_active`면 무조건 차단 판정에 쓰이고
   `ML_SHADOW_MODE`는 모델 로드 실패 시에만 참조된다 → shadow 수집도 3개월간 중단.
2. **판단 근거가 사실상 없다** — 로그 1,555쌍은 동일 종목 재평가 복제(05-14은 2종목을
   855회씩)라 (종목,일) 중복 제거 시 **독립 표본 3건**. "AUC 0.78"은 한 종목을 855번 센 결과.
3. **임계값이 분포와 어긋난다** — 학습 positive_rate 48.6% vs 라이브 점수 중앙값 0.147.
   임계 0.40이면 99.3% 차단. 모델이 보수적인 게 아니라 **prior shift**.

**지금 켜면 안 된다** — 켜면 99% 차단되어 오늘의 슬롯 확대가 무의미해진다.
CLAUDE.md는 실제 상태로 정정했다. 분석 전문: [research/20260825_2](../research/20260825_2_ml_gate_assessment.md)

## 6. 반드시 기억할 것

### 검증 룰은 "실패를 잡는지"로 검증한다 — 오늘만 초안이 3번 깨졌다

| 깨진 지점 | 원인 |
|---|---|
| `check_exit_reasons_classified` 초안 | 정규식이 `rebuilt["last_exec_price"]` **dict 키**를 청산 사유로 오인 |
| 같은 룰 | `periodic_analysis.py` **주석의 "trade_class"** 문자열에 속아 통과 |
| 기존 lessons #38 룰 | `floor` 대입을 지워도 **위 주석의 이름** 때문에 통과 (아무것도 못 잡는 상태였음) |

**"주석에 속는 룰"은 이 프로젝트에서 5회째다.** 문자열 포함이 아니라 **호출 형태**를 요구할 것.

### 실거래 표본과 파라미터 선택은 다른 질문이다

30건은 **체결가·필터·버그가 설계대로 도는가**를 보는 것이다.
파라미터 선택은 백테스트로만 가능하다(슬롯 15의 필요 표본 109건).

### 배포 순서 — state 마이그레이션이 있으면 봇을 먼저 멈춘다

**봇 정지 → 배포 → 마이그레이션 → 기동.** `hotfix_deploy.sh`는 재시작이 먼저라 쓸 수 없다.
게이트는 `.env`가 있는 **서버에서** `pre_deploy_check.py` 실행으로 대체한다.

### 로컬 PC 제약 (이 세션에서 겪음)

- `python`은 WindowsApps 스텁 — **`py -3`** 을 쓸 것. `deploy_to_aws.sh`가 이 때문에 안 돈다
- 로컬엔 `services/.env`가 없어 `pre_deploy_check.py`가 항상 `[ENV]` 오류 1건을 낸다(정상)
- Bash 힙독으로 파이썬 스크립트를 넘길 때 **백슬래시가 붕괴**한다(`\n` → 실제 개행).
  `chr(92)`로 조립하거나 유니코드 이스케이프를 쓸 것. 한글 리터럴도 인코딩이 깨질 수 있다
- 백테스트 sweep은 **매 실행 ~30분**을 데이터 로딩에 쓴다(`fetch_ohlcv` 캐시가
  요청 시작일을 커버 못 해 매번 재fetch). 여러 축은 한 프로세스에서 돌릴 것
