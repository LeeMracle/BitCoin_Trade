## 3. ⚠ 미수정 — 유령 포지션 버그 (최우선)

**증상**: SPK가 거래소 실보유 0, `remaining_qty` 0인데 `state["positions"]`에 남아 있다.
TP2가 08-23 14:03에 전량 매도(+3,013원)했으나 포지션이 제거되지 않았다.

**원인** (`services/execution/realtime_monitor.py:1799~`):

```python
for idx, tp in enumerate(TP_LEVELS):
    if idx in sold_levels:      # [0,1] 완료 → 매 반복 continue
        continue
    ...
        if cur_total <= 0:      # ← 잔고 0 자동정리. 여기까지 도달 못 함
            # closed_trades 기록 + positions 제거
```

잔고 0 자동정리(lessons #28)가 **TP 루프 안에** 있어서, 모든 TP 단계가 완료되면
루프가 전부 `continue`로 빠져나가 **도달 불가능**해진다.

**영향 3가지**

1. 슬롯을 영구 점유 → 신규 매수 차단 (현재 5/5인데 실제로는 4개)
2. `closed_trades`에 기록되지 않음 → **P1 검증 표본이 영원히 0에서 안 늘어남**
3. 보고서가 5종목 보유로 잘못 표시

**즉시성**: 이 버그는 **이익으로 청산된 거래**에서만 발생한다.
손절은 `_execute_sell`이 별도로 처리해 정상 제거된다.
즉 **잘 된 거래일수록 기록이 안 남는다.**

## 4. 다음 작업 — 5.5% 익절 전략 검토

사용자 의도: "5% 수익 내면 익절해서 수익 누적, 수수료 포함해 5.5%에 매도"

### 4-1. 수수료 계산은 맞다

업비트 현물 수수료 0.05% × 2(매수·매도) = 0.1%.
5.0% 익절 시 실수령 약 4.9%, 5.5% 익절 시 약 5.4%. 수수료를 덮으려는 판단은 타당하다.

### 4-2. 그러나 측정 데이터는 이 방향과 반대다

08-23 파라미터 탐색(`scripts/backtest_param_sweep.py`) 결과 — 무작위 선택 10회 평균, OOS:

| TP1 수준 | OOS 수익률 |
|---|---:|
| **현행 5% / 12%** | **+0.7%** ← 최하위권 |
| 5% / 30% 매도비율 | +3.8% |
| 10% | +5.8% |
| TP 없음 (트레일만) | +8.1% |
| **15%** | **+10.8%** ← 최상위 |

**TP1을 늦출수록 좋아진다.** 5.5%는 현행 5%와 사실상 같은 구간이므로
개선 효과는 거의 없을 것으로 예상된다.

원인: TP1이 +5%에서 절반을 실현하는데 손실은 -10%(하드캡)까지 간다.
**"자주 조금 이기고, 질 때 크게 지는"** 비대칭이 만들어진다.
실제로 TP를 늦추면 승률은 55%→47%로 **떨어지는데 수익은 오른다.**

### 4-3. 중요 — "전량 익절"이면 더 나쁠 수 있다

사용자 표현("익절해서 수익을 누적")이 **전량 매도**를 뜻한다면, 현행(50% 부분매도)보다
승자를 더 강하게 잘라내는 것이므로 측정된 방향과 더 크게 어긋난다.
**구현 전에 부분매도인지 전량매도인지 확인 필요.**

### 4-4. 반드시 먼저 고칠 것

**§3 유령 포지션 버그를 먼저 고쳐야 한다.**
5.5% 전량 익절이면 **승리 거래마다** 모든 TP 단계가 완료되므로 이 버그가 매번 발생한다.
슬롯이 유령으로 차서 거래가 완전히 멈출 수 있다.

### 4-5. 권고 순서

1. 유령 포지션 버그 수정 (+ 검증규칙, + SPK 수동 정리)
2. 5.5% 안을 `backtest_param_sweep.py`로 측정 — 부분/전량 두 경우 모두
3. 측정 결과를 근거로 사용자와 결정 (ADR 작성)
4. 실거래 반영은 그 다음

단, 지금 파라미터를 바꾸면 ADR 20260823-1의 검증 표본(0/30건)이 리셋된다는 점을 알릴 것.

아무것도 안 하고 있을 수 있다.
